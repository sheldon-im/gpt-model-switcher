# Mac 검증 · 2026-10-30

현재 판정: **Mac 0.1.3 설치 후보이며 실제 단축키 양방향 전환·VoiceOver 사용 검증은 미완료입니다.** 아래 초기 0.1.0 및 0.1.2 기록은 당시의 검사 범위로 보존하며, 현재 판단에는 후속 결과를 우선합니다.

## 0.1.3 앱 내부 접근성 처리 후속

0.1.2도 작동하지 않는다는 사용자 보고 후 실제 설정 창의 최근 결과에서 `접근성 권한이 필요합니다`와 `Release shortcut keys and retry` 오류를 직접 읽었습니다. 같은 설치 경로의 CLI를 진단 도구에서 실행하면 AX 읽기와 데스크톱 IPC 설정 읽기는 성공했지만, 실행 중 앱 자체의 권한 상태는 거부였습니다. 시스템 설정의 GPT Model Switcher 스위치는 켜져 있었고, 사용자가 다시 껐다 켠 후 동일 바이너리를 재시작해도 앱의 거부 상태는 남았습니다. CLI의 권한 결과를 실제 상주 앱의 권한으로 사용한 이전 검증은 충분하지 않았습니다.

접근성 호출·권한 요청·활성 앱 관찰·최종 접근성 안내를 Swift 정적 라이브러리로 앱 실행 파일에 연결했습니다. 별도 도우미 프로세스에 접근성 권한을 의존하지 않습니다. Swift CLI는 합성 검사 전용으로 분리했고 앱에 묶지 않습니다. Rust에서 실제 연결된 Swift ABI의 권한 상태 왕복·잘못된 요청 안전 처리를 추가로 검사하여 Rust 30개와 Swift 23건이 통과했습니다. 설치된 앱 안에서의 권한 판정은 최종 후보 설치 후 별도로 확인해야 합니다.

실제 실패 이력에 있던 보조 키 해제 대기도 Mac의 전환 경로에서 제거했습니다. 현재 Mac 전환은 키 전송 없이 AX 읽기와 조건부 IPC만 사용하므로 보조 키를 1초 안에 모두 떼어야 할 이유가 없습니다. 생성 중·문맥/소유자/포커스/선택값 검증은 유지하며 Windows 경로는 변경하지 않았습니다. 실제 키 입력을 통한 회귀 확인은 최종 설치본에서 진행합니다.

0.1.3 전체 빌드와 Rust30/React7/Swift23 검사를 통과한 뒤, 기존 0.1.2를 `outputs/backups/GPT Model Switcher-0.1.2-before-embedded-AX.app`로 보존하고 0.1.3을 설치·재시작했습니다. 서명된 앱 실행 파일에 Swift 코드가 포함되며, 앱 묶음과 실행 프로세스에 별도 macos-bridge는 없습니다. 새 임시 서명 파일에 대한 사용자 재허용을 요청했으며 이 파일을 다시 빌드하지 않은 상태로 권한 및 실기 확인을 진행합니다.

진단 도구에서 실제 활성 로컬 대화의 AX 선택값 Sol High와 생성 중 상태, IPC의 `model=gpt-6.1-sol`, `reasoningEffort=null`을 직접 읽었습니다. 설정 갱신 endpoint에도 현재 원시 값과 불일치 조건을 붙인 요청을 보내 `applied=false` 응답 및 모든 설정의 전후 동일을 확인했습니다. 진단 프로세스의 연결 시험이며 상주 앱이 모델을 변경했다는 증거는 아닙니다. 생성 중인 대화의 모델·추론은 바꾸지 않았고 메시지를 보내지 않았습니다. 실제 양방향 시험은 생성이 끝난 사용자 지정/승인 대화와 앱 권한 확인이 필요합니다.

## 단축키 실패와 권한 요청 후속

사용자는 0.1.0 설치 후 ChatGPT에서 Command+Option+Shift+1/2를 누르면 모델이 바뀌지 않고 큰 설정 창이 열린다고 직접 보고했습니다. 앞선 빌드·서명 통과는 이 실사용 실패를 발견하지 못한 자동 검사 결과입니다.

접근성 권한이 없을 때 검사 오류만 반환하던 경로를 보완했습니다. Mac 앱 시작 시 Apple의 `AXIsProcessTrustedWithOptions`와 prompt 옵션으로 OS 권한 요청을 실행하고, 설정 화면에 권한 상태·다시 요청·손쉬운 사용 권한 설정 열기를 제공합니다. 사용자 허용은 OS가 담당하며 앱이 강제로 허용하지 않습니다. 2초마다 및 창 복귀 시 권한 상태를 다시 읽고 편집 포커스는 옮기지 않습니다.

자동 요청은 앱이 종료될 때까지 살아 있는 활성 앱 관찰 도우미에서 수행합니다. 비동기 권한 안내를 요청한 직후 짧은 별도 프로세스가 종료되는 문제를 피하고, 수동 재요청도 짧게 이벤트 루프를 유지합니다.

권한 UI 보완 후 Rust 27개·React 7개·Swift 19건 검사가 통과했습니다. React의 추가 2건은 권한 요청/설정 열기 동작과 허용 후 상태 재확인·편집 포커스 보존 검사이며 실제 macOS 승인 창 또는 VoiceOver 청취 시험은 아닙니다.

큰 설정 창을 여는 경로를 조사하여 재실행 시 무조건 창을 표시하던 처리를 제거했습니다. 실행 중 인스턴스가 받은 일반 재실행·`--background` 요청은 창을 열지 않으며 `--settings`와 메뉴 막대의 설정만 명시적으로 창을 엽니다. 첫 일반 실행은 초기 설정을 보여줍니다. `--apply=ID`는 저장된 프리셋을 사용하는 상주 인스턴스에 전달하고 별도 프로세스의 기본값으로 실행하지 않습니다. 빈 ID·중복 실행 동작은 거부합니다.

실제 Mac AX 읽기에서 직접적인 화면 판별 결함도 확인했습니다. 전환용 `GPT-6.1 Sol High` 및 `권한 변경` 컨트롤의 역할은 `AXPopUpButton`인데 기존 코드는 `AXButton`만 허용했습니다. 일반 모델 표시 `GPT 6.1 Terra`와 실제 전환용 팝업을 구별하고, 기존 버튼 역할과 팝업 역할을 모두 읽도록 보완했습니다. 실제 라벨·역할을 재현한 Swift 합성 4건을 추가했습니다. 메뉴를 열거나 선택하지 않았습니다.

Mac 번들은 `LSUIElement`를 사용하는 메뉴 막대 앱으로 구성했습니다. 단축키의 시스템 이벤트 콜백은 관찰된 활성 앱 상태만 즉시 확인하고, 별도 Cocoa 도우미 실행은 전환 작업에서 수행합니다. 실제 쓰기 직전에는 기존 AX·소켓·대화·포커스 보호를 다시 검사합니다. 이 보완 후 Rust 29개 검사가 통과했습니다. 추가 2건은 재실행/설정/프리셋 요청 구분 검사이며 사용자가 보고한 키 입력 전체의 실제 해결 판정은 재시험 전입니다.

## 0.1.2 설치와 남은 사용자 시험

사용자는 이 대화에서 기존 앱을 백업한 뒤 `/Applications`의 설치본을 교체·재시작하도록 명시적으로 승인했습니다. 최초 교체 시도는 자동 승인 검토에서 거부되어 실행되지 않았으며, 사용자 승인 후 재시도했습니다. 재시도 직전 기존 0.1.0 앱과 프로세스가 이미 없어 안전 검사가 중단되었습니다. 제거 주체·원인은 확인하지 않았습니다. 기존 시험 DMG를 `outputs/backups/gpt-model-switcher-0.1.0-macos-arm64-test.dmg`로 보존하고 SHA-256 일치를 확인한 뒤 0.1.2를 설치했습니다. 사용자 설정 파일·ChatGPT 앱·TCC는 변경하지 않았습니다.

최종 후보는 Rust 29개·React 7개·Swift 23건 및 전체 빌드, 임시 서명 앱·도우미 검사, DMG 체크섬 검사를 통과했습니다. 앱의 `LSUIElement=true`, 설치 경로와 빌드 산출물의 바이너리 일치 및 상주 프로세스를 확인했습니다. 백그라운드 시작 점검에서 설정 창은 없었습니다. OS 권한 안내의 실제 표시·사용자 승인 완료는 별도 사용자 확인 대상입니다.

마지막 읽기 진단 시 전면 앱은 Moonlight였으며 로컬 ChatGPT는 활성 대상이 아니었습니다. 실제 모델 변경 요청은 보내지 않았고 두 프리셋 양방향 성공·작성문/선택/커서 보존·VoiceOver 청취/점자는 미검증입니다. Mac 앱은 로컬 ChatGPT만 대상으로 하며 원격 화면 안의 앱은 대상으로 삼지 않습니다. 응답이 끝난 뒤 사용자의 로컬 시험 대화에서 단축키를 다시 확인해야 합니다.

## 0.1.0 초기 읽기와 연결 검증

- 설치본의 ASAR에서 설정 읽기 v1 / 조건부 설정 갱신 v2와 모델·추론 조건 비교 구현을 직접 확인했습니다. 설치된 앱 소스는 수정하지 않았습니다.
- `$HOME/.codex/ipc/ipc.sock`이 현재 사용자 소유, `srw-------`인 소켓임을 확인했습니다. 커널의 `LOCAL_PEERPID`가 가리키는 실행 파일은 설치된 ChatGPT였습니다. 설정 요청·모델 변경 없이 상대 프로세스만 조회했습니다.
- 기존 Mac 연결 함수가 대상 PID를 무시하던 문제를 수정했습니다. 초기화 프레임을 보내기 전에 커널의 상대 PID가 AX 대상 PID와 같은지 검사합니다. 다른 PID, 그룹 접근 가능 소켓, 일반 파일은 거부합니다.
- 공통 원본 검사: Rust 26개, React 5개 통과. 프런트엔드 production 빌드 통과. 잠금 파일 변경 없음.
- 연결 보완 후 Rust 27개 통과. 추가 검사는 임시 Unix 소켓에 대한 커널 상대 PID·권한 검사이며 실제 대화 전환 시험이 아닙니다.
- 공개 [App Server 문서](https://learn.chatgpt.com/docs/app-server)를 기본 웹 검색·Firecrawl로 확인했습니다. 공개 문서는 내부 데스크톱 IPC의 호환성 보증으로 사용하지 않습니다.

- 초점 창이 없거나 AX 창 목록이 정확히 하나가 아니면 중단합니다. 여러 창을 같은 제목·포커스 경로로 혼동하지 않도록 보수적으로 거부합니다.
- 누락·손상·만료된 문맥 토큰을 AX 읽기 전에 거부하고, `check` 인수가 없을 때 배열 범위 오류로 종료되던 경로를 수정했습니다.
- 초기 Swift 검사는 합성 문맥·PID·문서·포커스 변경·한/영 선택값 14건과 잘못된 요청 5건이었습니다. 0.1.2에서는 팝업 역할·실제 라벨 4건이 추가되어 합성 18건과 잘못된 요청 5건입니다. AX 객체를 만든 모의 네이티브 앱이나 실제 VoiceOver 시험은 아닙니다.

## 실제 앱과 접근성 검증 경계

초기 0.1.0 검사에서는 접근성 권한 필요 오류로 실제 설정 읽기/전환을 진행하지 못했습니다. 후속 조사에서는 권한 있는 읽기 전용 진단으로 창과 버튼의 AX 역할·라벨을 확인해 팝업 판별 결함을 찾았습니다. TCC 수정이나 권한 강제 부여는 수행하지 않았습니다. 도우미의 직접 실행에서 확인한 권한 결과를 설치된 앱의 사용자 승인 완료로 간주하지 않습니다.

아래 항목은 모두 **미시험**입니다.

- 사용자 지정 기존 대화에서 Terra medium / Sol high 양방향 전환과 원래 설정 복구.
- 실제 작성문·선택 영역·커서 보존, 두 창·동일 제목·클라우드/원격 대화·생성 중 상태의 실기 차단.
- 실제 VoiceOver 입력 포커스·커서·점자 보존과 최종 결과 1회 안내, 안내 끄기·한국어/영어·고대비.

접근성 권한은 사용자가 시스템 설정에서 직접 부여해야 합니다. 이 결과는 Windows의 NVDA 실패가 Mac에서 해결되었다는 판정이 아닙니다. 실제 프롬프트 전송·정식 서명·공증·공개 배포·자동 시작 등록은 수행하지 않습니다.

## 0.1.0 초기 빌드와 로컬 시험 패키지

- `sh scripts/build-macos.sh`로 잠금 파일을 유지한 의존성 설치, Rust 27개·React 5개·Swift 19건 검사, 프런트엔드 빌드와 arm64 release 앱 생성을 확인했습니다.
- 최초 DMG 시도는 Finder 장식 AppleScript가 대기하여 그 하위 작업을 중단했습니다. `CI=true`와 `--ci`를 사용한 포장 재실행은 종료 코드 0으로 앱/DMG를 생성했습니다. 이후 빌드 스크립트에도 같은 비대화형 모드를 적용했습니다.
- 최종 `sh scripts/build-macos.sh` 전체 재실행도 종료 코드 0으로 완료했습니다. 설정·DB·인증 자료·도구 캐시는 소스 패키지에 포함하지 않습니다.
- Swift 모듈 캐시를 Cargo 출력 폴더와 `target` 내부로 지정했습니다. Mac에서 사용되지 않는 Windows 알림 핸들의 컴파일 경고도 제거했습니다.
- 앱과 포함된 도우미 모두 arm64이며 `codesign --verify --deep --strict` 통과, `codesign -dv`에서 `Signature=adhoc`, `TeamIdentifier=not set`을 확인했습니다.
- DMG의 `hdiutil verify` 체크섬 검사가 통과했습니다.
- Gatekeeper의 `spctl --assess --type execute` 결과는 **rejected (종료 코드 3)**입니다. 공증·Developer ID 서명·Gatekeeper 통과로 표시하지 않습니다. 보안 설정이나 격리 속성을 변경하지 않았습니다.
- 묶음 앱의 `--inspect`도 접근성 권한 필요 상태를 정상 JSON으로 반환했습니다. GUI 설정 창의 실제 키보드 탐색·백그라운드 시작 시 포커스 보존은 아직 미시험입니다.

## 사용자가 이어서 확인할 순서

1. Finder에서 `Command+Shift+G`로 이 폴더의 `target/aarch64-apple-darwin/release/bundle/macos`를 열고 `GPT Model Switcher.app`을 찾습니다. 설치·최초 실행 허용 여부는 사용자가 선택합니다.
2. 시스템 설정의 **개인정보 보호 및 보안 → 손쉬운 사용**에서 앱과 필요한 도우미의 권한을 직접 허용합니다. Tab/Shift+Tab 또는 VoiceOver 탐색키로 항목과 추가 버튼을 찾아 조작합니다. 이 경로 안내는 실제 사용자 검증과 구별합니다.
3. 실제 전환 시험에 사용할 기존 로컬 대화 하나를 지정합니다. 생성이 끝난 상태에서 한글/영문 작성문·선택 영역·커서를 기록하고 두 프리셋을 시험한 뒤 원래 모델·추론 값으로 복구합니다. 메시지는 보내지 않습니다.
4. VoiceOver로 입력 포커스·VO 커서·점자가 유지되고 최종 안내가 한 번인지 확인합니다. 실패·미확인은 이 문서에 별도로 기록하며 자동 검사 통과로 대체하지 않습니다.
