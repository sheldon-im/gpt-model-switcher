# 검증 상태 · 2026-10-30

수행자: Windows의 Codex. 대상: Windows 11 x64의 로컬 소스 및 설치된 ChatGPT desktop 26.1027.3384.0. 설치·유료 가입·실제 프롬프트 전송은 수행하지 않았습니다. 사용자의 후속 명시적 승인에 따라 `gh`로 [sheldon-im/gpt-model-switcher](https://github.com/sheldon-im/gpt-model-switcher) private 저장소를 만들었습니다. 이어 사용자 지정 공유 드라이브의 Mac 0.1.4 수정본을 Windows 0.1.2에 통합하여 0.1.5로 구분합니다. `isPrivate=true`를 확인한 뒤 소스와 커밋 이력을 올리며 공개 전환이나 시험 패키지 외부 배포는 하지 않습니다.

## 현재 판정

**시험 후보이며 실사용 검증 완료가 아닙니다.** 메뉴 자동화의 포커스·읽기 문제는 사용자의 실제 NVDA 관찰로 확인된 실패입니다. 이를 해결하기 위해 기본 동작에서 메뉴·키 전송·포커스 설정을 제거했습니다. 새 방식의 실제 NVDA 최종 안내/점자 및 실제 앱 양방향 전환은 재검증 전입니다. Mac 빌드와 VoiceOver 실기는 Mac Codex에게 인계합니다.

## 0.1.5 Windows / Mac 통합

Mac 원본 `9007544`와 검증 기록 `docs/MAC_VERIFICATION.md`를 가져왔습니다. 이 기록에는 Mac 0.1.4의 Rust32/React7/Swift23 및 임시 서명·DMG 검사, 사용자 전환 정상 보고가 있습니다. 이 Windows 작업자가 Mac에서 독립 재현한 결과는 아닙니다. 통합본의 Mac 빌드·권한·VoiceOver는 재검증 전입니다.

이번 Windows 통합 검사에는 기존 NVDA/동일 프리셋 보호, 표준/Work 모델 캐시 우선순위·손상/시각/크기 제한, 시작/재실행/명시적 프리셋 요청, 권한 UI의 편집 포커스 보존, 상주 진단 재기록의 설정 보존을 포함합니다. Mac 원본 폴더는 변경하지 않습니다. 원본 커밋 이력은 통합 이력의 부모 및 보존 브랜치로 연결합니다. 기능·검증 경계와 차이는 `docs/INTEGRATION.md`를 참조하십시오.

## 0.1.2 반복 단축키 후속

사용자는 0.1.1의 ‘모델 전환 음성 피드백 시험입니다’ 안내가 **한 번 들렸다**고 회신했습니다. 이것은 단일 시험 안내의 실제 청취 확인이며, 실제 프리셋 전환 전체·점자·VoiceOver 통과를 의미하지 않습니다. 같은 프리셋에 해당하는 키를 다시 누를 때의 처리를 추가 요청했습니다.

실제 모델·추론을 재확인한 뒤 둘 다 맞을 때만 `already_applied` 결과를 반환하며 모델/추론 설정 쓰기·복구·포커스 복귀 조작을 생략합니다. 안내는 한국어 ‘이미 적용되어 있습니다’ 또는 영어 ‘Already applied’로 구분하고 모델·추론을 한 번 포함합니다. 화면과 최근 결과도 구분하며 웹 live region을 추가하지 않습니다. 이 확인 전에 응답 중/문맥/포커스 검사는 그대로 적용합니다.

자동 검사에서 같은 키의 반복 적용 시 쓰기 0회, 기본 추론 null 보존, 같은 모델/다른 추론의 실제 변경, 재확인 중 값 변경의 성공 오표시 방지, 한국어/영어 안내, 최근 결과와 화면 알림의 별도 표시 및 포커스 보존을 확인했습니다. 새 반복 단축키 처리의 실제 앱 청취와 Mac 실기는 미확인입니다.

## 0.1.1 후속 음성 회귀 수정

사용자는 0.1.0에서 포커스로 인한 소란은 없어졌지만 프리셋 변경 음성이 나오지 않는다고 보고했습니다. 이 보고를 사용자 관찰로 기록하며, 전체 접근성 통과로 확대하지 않습니다. 기존의 숨긴 창 UIA 알림이 실제 NVDA 피드백으로 전달되지 않는 경로를 NVDA 공식 Controller Client 우선 경로로 교체했습니다. UIA가 어느 단계에서 거부되었는지까지 독립 추적한 것은 아닙니다.

- 공식 NV Access 2026.3의 x64 DLL을 다운로드하여 원본 서명 Valid, SHA256 및 공식 소스 태그를 확인했습니다. LGPL 라이선스와 전체 원본 대응 소스를 동봉합니다. 사용자 NVDA 설치/설정을 바꾸지 않습니다.
- 실제 실행 중인 NVDA 연결 검사 반환값 0을 확인했습니다. 이어 네이티브 실행 파일의 안내 시험에서 음성·점자 요청이 수락됐고 전경 창이 유지됨을 확인했습니다. 요청 수락은 실제 음성 청취·점자 판독의 성공과 구분합니다.
- 자동 검사는 한 번의 음성/점자 전송, 음성 거부 오류, 점자 실패 후 음성 중복 방지, NVDA 성공 후 UIA 중복 방지, NVDA 부재의 UIA 경로, 보안/접근 오류의 무조건 재시도 방지, 안내 시험 버튼의 포커스·사용자 안내 끄기 존중을 포함합니다.
- 0.1.1 당시 기본 모델 전환 코드는 변경하지 않았습니다. 사용자가 후속 회신에서 단일 시험 안내를 한 번 들었다고 확인했습니다. 프리셋 전환 중 실제 청취 및 Mac/VoiceOver 실기는 계속 별도 확인 대상입니다.

## 새 방식의 동작 경계

1. 앱 이미지·활성 창·문서 제목·로컬 작업 컨트롤·모델 버튼을 읽습니다. Windows는 접근성 클라우드/원격 표시가 있으면 거부합니다. 같은 제목의 로컬 기록이 여러 개이면 거부합니다. 새 대화/클라우드/원격 호스트/지원하지 않는 모드는 지원 완료로 표시하지 않습니다.
2. 읽기 전용 `state_5.sqlite`에서 정확한 제목의 로컬 식별자를 찾습니다. Windows pipe는 foreground 앱 PID와 서버 PID가 같아야 합니다. Mac 소켓은 현재 사용자 소유권과 제한된 권한을 확인합니다. 임의 서버를 시작하지 않습니다.
3. 등록 후 대화 소유자의 설정 응답을 읽고 소유자를 고정합니다. 공개되지 않은 IPC 버전이 일치하지 않거나 화면 모델과 설정이 다르면 중단합니다. 앱의 모델 캐시에 해당 조합이 있으며 하루 이내인지 확인합니다. 이 캐시가 실시간 계정 권한을 보장하지는 않습니다.
4. 모델·추론을 한 요청으로 적용하며 직전 모델/추론의 조건을 함께 전달합니다. 메시지, turn/start, resume, 권한 변경 API는 호출하지 않습니다. null 기본 추론값은 복구 시 명시적 high로 바꾸지 않고 null로 돌립니다.
5. 실제 화면 선택값과 소유자 설정이 모두 일치해야 성공입니다. 포커스나 문맥이 바뀌면 추가 조작을 중단합니다. 되돌릴 때도 방금 적용한 값이 그대로인지 조건을 확인합니다.
6. 화면 알림은 Windows SW_SHOWNOACTIVATE, Mac orderFront를 사용하며 별도 포커스를 받지 않습니다. NVDA가 실행 중이면 공식 Controller Client로 최종 음성 1건과 점자 1건을 전달합니다. NVDA가 없을 때만 일반 Windows UIA 안내를 시도합니다. Mac은 accessibility announcement를 사용합니다. 웹 결과 목록과 화면 알림은 같은 결과를 live region으로 중복 읽지 않습니다. API 호출 성공과 실제 음성 전달은 별도 판정입니다.

## 사용자 실기 확인표

- 사용자가 선택한 시험용 기존 로컬 대화에서 응답이 끝난 상태로 진행합니다. 새 메시지는 보내지 않습니다.
- 입력창에 한글/영문 작성문을 남기고 선택 영역과 커서 위치를 기록합니다. 각 프리셋 적용 후 모델/추론 값과 작성문/선택/커서가 그대로인지 확인합니다.
- NVDA Speech Viewer/점자 및 실제 청취로 중간 메뉴 읽기·포커스 이동이 없고 최종 결과가 한 번만 전달되는지 확인합니다. 필요하면 안내를 끄고 화면/최근 결과만 사용합니다. 별도 TTS나 전역 음소거를 켜지 않습니다.
- 응답 중, 같은 제목, 클라우드/로컬의 제목 충돌, 두 창, 다른 앱, 단축키 충돌, 앱/대화/포커스 전환, 연속 누름에서 오작동·성공 오표시가 없는지 확인합니다.
- 원래 선택값으로 되돌리고 시험 날짜·앱/NVDA 버전·실제 결과를 기록합니다. 실패면 그대로 미통과로 남깁니다.

## 근거

프로토콜은 이 PC의 설치된 `app.asar`의 framing/router/thread-settings 구현을 읽어 확인했습니다. 설치된 앱 파일이나 글로벌 스크린 리더 설정은 수정하지 않았습니다. 공개 지원 계약이 아니므로 업데이트 후 재검증이 필요합니다.

Windows UIA 초기 문서 읽기 실패 시 COM 정리가 중복되는 경로를 정리했습니다. 이후 공통 검사·Windows 빌드·실제 읽기 진단으로 회귀를 확인하며, 실제 UIA 공급자 고장 주입 검사는 수행하지 않았습니다.

- [ChatGPT desktop commands](https://learn.chatgpt.com/docs/app/commands)
- [App-server](https://learn.chatgpt.com/docs/app-server)
- [Tauri global shortcuts](https://v2.tauri.app/plugin/global-shortcut/)
- [Tauri macOS signing](https://v2.tauri.app/distribute/sign/macos/)
- [Apple Developer Program](https://developer.apple.com/programs/)
- [NVDA Controller Client 공식 문서](https://github.com/nvaccess/nvda/blob/release-2026.3/extras/controllerClient/readme.md)

공식 문서는 제품·빌드 안내의 근거이며 이 비공개 IPC의 외부 지원이나 실제 NVDA/VoiceOver 성공을 보증하는 자료가 아닙니다.
