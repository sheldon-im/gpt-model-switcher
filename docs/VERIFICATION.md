# 검증 상태 · 2026-10-30

수행자: Windows의 Codex. 대상: Windows 11 x64의 로컬 소스 및 설치된 ChatGPT desktop 26.1027.3384.0. 원격 게시·설치·유료 가입·실제 프롬프트 전송은 수행하지 않았습니다.

## 현재 판정

**시험 후보이며 실사용 검증 완료가 아닙니다.** 메뉴 자동화의 포커스·읽기 문제는 사용자의 실제 NVDA 관찰로 확인된 실패입니다. 이를 해결하기 위해 기본 동작에서 메뉴·키 전송·포커스 설정을 제거했습니다. 새 방식의 실제 NVDA 최종 안내/점자 및 실제 앱 양방향 전환은 재검증 전입니다. Mac 빌드와 VoiceOver 실기는 Mac Codex에게 인계합니다.

## 새 방식의 동작 경계

1. 앱 이미지·활성 창·문서 제목·로컬 작업 컨트롤·모델 버튼을 읽습니다. Windows는 접근성 클라우드/원격 표시가 있으면 거부합니다. 같은 제목의 로컬 기록이 여러 개이면 거부합니다. 새 대화/클라우드/원격 호스트/지원하지 않는 모드는 지원 완료로 표시하지 않습니다.
2. 읽기 전용 `state_5.sqlite`에서 정확한 제목의 로컬 식별자를 찾습니다. Windows pipe는 foreground 앱 PID와 서버 PID가 같아야 합니다. Mac 소켓은 현재 사용자 소유권과 제한된 권한을 확인합니다. 임의 서버를 시작하지 않습니다.
3. 등록 후 대화 소유자의 설정 응답을 읽고 소유자를 고정합니다. 공개되지 않은 IPC 버전이 일치하지 않거나 화면 모델과 설정이 다르면 중단합니다. 앱의 모델 캐시에 해당 조합이 있으며 하루 이내인지 확인합니다. 이 캐시가 실시간 계정 권한을 보장하지는 않습니다.
4. 모델·추론을 한 요청으로 적용하며 직전 모델/추론의 조건을 함께 전달합니다. 메시지, turn/start, resume, 권한 변경 API는 호출하지 않습니다. null 기본 추론값은 복구 시 명시적 high로 바꾸지 않고 null로 돌립니다.
5. 실제 화면 선택값과 소유자 설정이 모두 일치해야 성공입니다. 포커스나 문맥이 바뀌면 추가 조작을 중단합니다. 되돌릴 때도 방금 적용한 값이 그대로인지 조건을 확인합니다.
6. 화면 알림은 Windows SW_SHOWNOACTIVATE, Mac orderFront를 사용하며 별도 포커스를 받지 않습니다. 스크린 리더에는 Windows UIA notification / Mac accessibility announcement 한 건만 요청합니다. 웹 결과 목록과 화면 알림은 같은 결과를 live region으로 중복 읽지 않습니다. API 호출 성공과 실제 음성 전달은 별도 판정입니다.

## 사용자 실기 확인표

- 사용자가 선택한 시험용 기존 로컬 대화에서 응답이 끝난 상태로 진행합니다. 새 메시지는 보내지 않습니다.
- 입력창에 한글/영문 작성문을 남기고 선택 영역과 커서 위치를 기록합니다. 각 프리셋 적용 후 모델/추론 값과 작성문/선택/커서가 그대로인지 확인합니다.
- NVDA Speech Viewer/점자 및 실제 청취로 중간 메뉴 읽기·포커스 이동이 없고 최종 결과가 한 번만 전달되는지 확인합니다. 필요하면 안내를 끄고 화면/최근 결과만 사용합니다. 별도 TTS나 전역 음소거를 켜지 않습니다.
- 응답 중, 같은 제목, 클라우드/로컬의 제목 충돌, 두 창, 다른 앱, 단축키 충돌, 앱/대화/포커스 전환, 연속 누름에서 오작동·성공 오표시가 없는지 확인합니다.
- 원래 선택값으로 되돌리고 시험 날짜·앱/NVDA 버전·실제 결과를 기록합니다. 실패면 그대로 미통과로 남깁니다.
